# 道路タイル モデル納品仕様

プロシージャル生成される街の「地面タイル」用モデルの納品仕様です。建物モデルとは別仕様になります。

## 1. 大原則（最重要）

### 決められた大きさのタイルを、用途ごとに1つのモデルとして分離する

コード側が**3m × 3mのマス目に沿ってタイルを敷き詰めて街を生成します**。タイルの大きさは用途ごとに決まっています（第2章の一覧を参照）。
- 生活道路：1マス（3m × 3m）
- 幹線道路：半幅タイル（3m × 6m）、交差点四半分タイル（6m × 6m）
- 横断歩道：全幅版（3m × 12m）、半幅版（3m × 6m）

複数の要素を1モデルに結合されると使用できません。

> 以前いただいた `Road.fbx` / `CrossRoad.fbx` は、歩道・横断歩道・道路が1つのモデルに結合されていたため使用できませんでした。今回はすべて新規に、**用途ごとに分離した状態**で作成をお願いします。

| してほしいこと | してほしくないこと |
| :---- | :---- |
| 決められた大きさ・用途ごとに1モデルにする | 道路＋歩道＋横断歩道をまとめて1モデルにする |
| 交差点は四半分（6m × 6m）を1モデルにする | 交差点全体（十字路まるごと、12m × 12m）を1モデルにする |

### 隣同士がシームレスに繋がること

同じタイルを縦横に並べて敷き詰めるため、タイルの端で模様・色・高さが途切れないようにしてください。

### 当たり判定（Collider）は不要

コード側で自動生成します。**見た目のモデルのみ**作成してください。

### 単一マテリアル・単一サブメッシュ必須

生成処理でタイルを1つのメッシュに結合するため、1モデルにつきマテリアルは1つ、サブメッシュも1つにしてください。複数マテリアルを使うと結合時に見た目が崩れます。

## 2. 必要なモデル一覧

| 優先度 | 用途 | サイズ（実寸） | 模様の想定 | 備考 |
| :---- | :---- | :---- | :---- | :---- |
| 高 | 幹線道路 半幅 | **3m × 6m** | 歩道側にL型側溝、中央側にセンターライン（半分の幅） | **非対称**。第4章「幹線道路 半幅タイル」を必ず参照 |
| 高 | 幹線道路 交差点四半分 | **6m × 6m** | 無地または簡素な舗装。外角のみ歩道の角 | 第4章「交差点四半分タイル」を必ず参照 |
| 高 | 横断歩道（全幅版） | **3m × 12m** | 縞模様 | 道路の全幅を1枚でまたぐ。第4章の注記を必ず参照 |
| 高 | 横断歩道（半幅版） | **3m × 6m** | 縞模様 | 全幅版のちょうど半分。第4章の注記を必ず参照 |
| 中 | 生活道路 縁（歩道側） | 3m × 3m | L型側溝 | 細街路用。幹線用とは別デザイン可 |

幹線道路は、**「半幅」と「交差点四半分」の2種類だけ**で組み立てます。

- 幅12mの幹線道路は、半幅タイル2枚を中央で背中合わせに並べて作ります（片方は180度回転）。
- 地形の生成単位（チャンク）の境目にある道路は、両側の生成単位が半幅タイルを1枚ずつ出して12mになります。
- 十字路（12m × 12m）は、交差点四半分タイル4枚を回転させて並べて作ります。
- 全幅（3m × 12m）の道路タイル、1マス（3m × 3m）の幹線道路タイル、境目専用のタイルは**不要**です。

## 3. サイズ・ピボット

| 項目 | 指定 |
| :---- | :---- |
| サイズ | 第2章の一覧のとおり（**実寸**。コード側で伸縮はしません） |
| 厚み | **平面（厚みなし）**、上面が Y = 0 |
| ピボット | **幾何中心**（XZ方向の中心、高さはY=0） |
| スケール | 1（Blender側でApply Transform済みの状態） |

## 4. 向きの規約（重要）

コード側がタイルを0°/90°/180°/270°に回転させて使い回すため、**モデルの向きの基準を揃える必要があります**。

### 基準

- **模様の「線」が伸びる方向** → ローカル **+Z軸**
- **非対称な要素（L型側溝など）のオフセット方向** → ローカル **±X軸**

### 図解（上から見た図）

```
        +Z
         ↑
    ┌────┼────┐
    │    │    │   ← 模様の線（センターライン等）は
    │    │    │      +Z方向に伸びる
    │    │    │
 ───┼────┼────┼─── → +X
    │    │    │
    │    │    │   ← 側溝などの非対称要素は
    │    │    │      X方向の片側に寄せる
    └────┴────┘
```

この規約を守っていただければ、コード側が縦向きの道路・横向きの道路・左右反転のすべてを自動で処理します。逆にこの基準がずれていると、側溝が道路の中央を向くなどの不具合になります。

### 幹線道路 半幅タイル（3m × 6m）

```
           +Z（道路の進む方向、3m）
            ↑
    ┌──────────────┐
    │▌            ┆│
    │▌            ┆│   ▌ = L型側溝（歩道側）
    │▌            ┆│   ┆ = センターライン（線幅の半分だけ）
    └──────────────┘
   −X端          +X端 → +X（道路を横切る方向、6m）
  （歩道側）   （道路の中央側）
```

- **−X端が歩道側**（L型側溝を置く側）、**+X端が道路の中央側**です。
- センターラインは**+X端に、線幅の半分だけ**描いてください。2枚が+X端どうしで背中合わせに並び、1本の線になります。
  - 生成単位の境目でも、+X端どうしが突き合わさります。
- **Z方向（進行方向）に対称**にしてください。
  - 反対側の車線では180度回転して使うため、Z方向の前後が逆になります。
  - 破線にする場合は、タイルの中央を基準に前後対称に配置してください。
- 進行方向に同じタイルを並べるため、±Z端で模様が途切れないようにしてください。

### 交差点四半分タイル（6m × 6m）

```
           +Z
            ↑
    ┌──────────────┐
    │              │   4枚が(+X, +Z)の角に集まって十字路（12m × 12m）になる
    │              │
    │              │
    │◣             │   ◣ = 交差点の外角（歩道の角に面する角）
    └──────────────┘  → +X
  (−X, −Z)の角
```

- **(−X, −Z)の角が交差点の外角**（歩道の角に面する角）です。
- 残りの辺はすべて道路（横断歩道または隣の四半分タイル）に接します。
- 4枚を90度ずつ回転させて並べ、**(+X, +Z)の角で4枚が合わさって**十字路になります。合わさる部分で模様が途切れないようにしてください。

### 横断歩道についての注記（重要）

幹線道路の横断歩道は、**道路の幅いっぱいを1枚でまたぐ形**で作っていただきます。幅で分割されないため、縞の本数・間隔を全幅で自由に設計できます。

| 種類 | サイズ | 用途 |
| :---- | :---- | :---- |
| 全幅版 | **3m × 12m**（実寸） | 通常の横断歩道。道路の全幅をまたぐ |
| 半幅版 | **3m × 6m**（実寸） | 全幅版のちょうど半分。地形の生成単位の境目で使う |

半幅版には守っていただきたい条件が2つあります。

**条件1：180度回転しても同じに見える対称な形にする**

半幅版は、置かれる場所によって向きが反転します。左右どちらを向いても破綻しないよう、縞の並びが**両端から読んで同一**になるように作ってください。

**条件2：2枚を突き合わせたときに、全幅版と同じ縞のリズムになる**

半幅版は2枚が背中合わせに並んで、全幅版と同じ12mを構成します。このとき縞の間隔が均等に繋がる必要があります。

```
良い例（端が半分の余白で始まる）
  半幅版1枚      ：[余白][縞][間隔][縞][余白]
  2枚並べたとき  ：[余白][縞][間隔][縞][余白余白][縞][間隔][縞][余白]
                                    └─ 間隔として自然に繋がる

悪い例（端が縞で始まる）
  半幅版1枚      ：[縞][間隔][縞]
  2枚並べたとき  ：[縞][間隔][縞][縞][間隔][縞]
                              └─ 縞が2本くっついてしまう
```

## 5. Blenderでのエクスポート設定

| 設定 | 値 | 理由 |
| :---- | :---- | :---- |
| **Apply Transform** | **オン** | 本プロジェクトのデータでは、オフだと読み込み時に不要な回転がかかることを確認済み（Blender公式には実験的機能と案内されていますが、オンにしてください） |
| スケール | 1 | |
| メッシュ | 統合済み（1オブジェクト） | |

## 6. 命名規則

建物モデル（`建物大_高レア_1.fbx` 等）に倣い、用途が分かる日本語名でお願いします。

例：
- `道路_幹線_半幅.fbx`
- `道路_幹線_交差点四半分.fbx`
- `道路_生活_縁.fbx`
- `横断歩道_全幅.fbx`
- `横断歩道_半幅.fbx`

## 7. 前提条件・未確定事項（プロジェクト内部向け）

この章はCG班向けではなく、開発側の申し送り事項です。

- **納品時の受け入れテスト**：確認項目は[基本設計.md](基本設計.md)の「やる事：道路タイルの実アセット納品時のテスト項目」にまとめてある。向き・継ぎ目・高さ・頂点数・当たり判定を確認する。

- **コード側の対応状況**：
  - 幹線道路の半幅・交差点四半分、横断歩道の全幅・半幅は、実寸配置（`prefab.transform.localScale`、納品物ならスケール1）で対応済み（2026-09-24）。`majorRoadHalfPrefab`／`majorRoadIntersectionQuarterPrefab`／`crosswalkBarPrefab`／`boundaryCrosswalkBarPrefab`に割り当てれば使われる。`GlobalLattice`モード限定。
  - 生活道路の1マス版タイル（`localRoadEdgePrefab`、横断歩道の1マス版）は、まだ `scale = (cellWidth, 1, cellHeight)` が掛かるため1×1ユニットのメッシュが前提。実寸3mでの納品を受けるには、`BuildGroundTilesRoutine`の1マス版の配置を実寸に揃える修正が必要。
  - メッシュ結合（`AddCombineInstance`）は子オブジェクトのTransformを反映しない。ピボットが幾何中心でないと位置がずれる。
  - 平面（厚みなし）で納品を受けるには、タスク13（地面タイルのCube→平面化）の実施が必要。現在の地面タイルはUnity組込みCube（1ユニット厚、上面Y=+0.5）。
- **厚みゼロか、薄い厚みを残すかは未決定**：厚みゼロの地面は高速走行時にすり抜け（トンネリング）が起きる可能性がある。対策として薄い厚み（0.1m程度）を残すか、車側のRigidbodyをContinuous判定にするかの検討が必要。
- **T字路・L字路は発生しない前提**：`GlobalLattice`の格子線はチャンクを端から端まで貫くため、交差点はすべて十字路になる（継ぎ目・四隅は十字路の一部を各チャンクが分担する）。設計の経緯は[基本設計.md](基本設計.md)の「仕様変更（2026-09-24）：幹線道路を「半幅タイル＋交差点四半分タイル」で組む方式へ移行」を参照。
