敵の生成・削除
動作確認チェックリスト
[EnemySpawnTest.unity](../Scenes/EnemySpawnTest.unity)をUnity Editorで開き、Play Modeに入って確認する。確認できたら[x]にする。


0. 事前確認（インポート・参照エラーがないか）
- [ ] シーンを開いた時点でConsoleにエラーが出ていない（特に`Missing Script`や`Missing Reference`）。
- [ ] `Enemy.prefab`と`EnemyPhaseSettings.asset`は、`.meta`ファイルを手動作成したもの（GUIDの衝突が無いことは確認済みだが、Unity側で実際に正しくインポートされているかは未確認）。ProjectウィンドウでアイコンやInspectorの表示が壊れていないか確認する。
- [ ] `EnemySpawnManager`（Hierarchy内）を選択し、Inspectorの`Phase Settings`に`EnemyPhaseSettings`アセットが正しく割り当てられている（Noneになっていない）ことを確認する。


1. 生成（M-1）
- [ ] Play開始後、しばらくすると（序盤フェーズの生成間隔3秒ごと）プレイヤーの周囲に敵が自動的に現れる。
- [ ] 生成された敵が地面に正しく接地している（沈み込んでいない／浮いていない）。`spawnPositionY`（既定0.85）が地面の高さと合っているか確認する。
- [ ] ビル群自動生成システムを使った状態（建物・道路が生成済みの範囲）でも、敵が建物に埋まって生成されない。埋まって見える場合は`spawnOverlapCheckRadius`／`maxSpawnPositionAttempts`の調整、またはビル側のColliderが正しく設定されているか確認する。
- [ ] デバッグ用に`debugForceSpawnOnOverlapFailure`を`true`にしておくと、重ならない位置が見つからなかった場合でも最後の候補位置へ強制的に生成し、`EnemySpawnManager: 生成位置がColliderと重なっていましたが...`という警告ログ（黄色）が出る。これを目印に、実際に埋まっている場所を歩いて探して確認する。**本来の挙動（見送り）を確認したい場合、または最終確認時はfalseに戻すこと**。
- [ ] 生成される敵は、プレイヤーから近すぎる位置（`minSpawnRadius`=15未満）には出ない。
- [ ] 生成される敵は、プレイヤーから遠すぎる位置（`maxSpawnRadius`=40超）には出ない。
- [ ] 同時に存在する敵の数が、現在のフェーズの`maxActiveEnemies`（序盤=10）を超えない。


2. 削除・デスポーン（M-2）
- [ ] プレイヤーから離れた敵（`despawnRadius`=60超）が、そのうち自動的に消える。
- [ ] `thinningRadius`（45）〜`despawnRadius`（60）の間にいる敵は、時間が経つと低確率（`thinningChancePerCheck`=1%/判定）で消えることがある。すぐには消えないことも多いはずなので、気長に確認する。
- [ ] `thinningRadius`（45）より近い距離にいる敵は、上記の間引きでは消えない（近くにいる敵が理由なく消えないことを確認する）。
- [ ] 攻撃して倒した敵（HP0）は、今まで通り即座に消える（`EnemyHealth.Die()`の挙動。プーリングとは別経路のため、従来と変わらないはず）。倒した直後にエラーが出ないことも確認する。


3. フェーズ切り替え（M-3）
- [ ] フェーズが切り替わるとConsoleに`EnemySpawnManager: フェーズ変更 ○○ → ××（経過時間: ...秒）`というログが出る（`EnemySpawnManager.RefreshPhase()`が出力）。切り替わりのタイミングはこのログで確認できる。
- [ ] 開始から180秒経過すると「中盤」に切り替わり、生成間隔が速くなる（3秒→2秒）。
- [ ] 開始から360秒経過すると「終盤」に切り替わり、さらに速くなる（2秒→1.5秒）。同時出現数上限も20に増える。
- [ ] 開始から540秒経過すると「ボス戦」に切り替わり、生成間隔が最速（1秒）になる一方、同時出現数上限は5に下がる。
- [ ] 上限が下がった直後（終盤→ボス戦）、既にいる敵が20体近くいた場合でも、それらが強制的に消されるわけではない（自然にデスポーンして5体を下回るまで新規生成が止まるだけ）ことを確認する。これは仕様通りの挙動であり、不具合ではない。


4. 既知の制約（今の設定では確認できない項目）
- [ ] `clearPreviousPhaseEnemiesOnEnter`（ボス戦のみtrue）は、現状すべてのフェーズが同じ`Enemy.prefab`を参照しているため効果が見えない。敵プレハブを複数種類用意し、フェーズごとに異なるプレハブを割り当てるようになってから改めて確認する。
- [ ] プーリング（Destroyせず非アクティブ化して再利用している）こと自体は、見た目では区別しづらい。気になる場合はUnity ProfilerでInstantiate/Destroyの呼び出し回数を計測するか、`EnemyPool`に一時的なデバッグログを仕込んで確認する。


5. パフォーマンス（参考）
- [ ] プレイを続けても（特にフェーズが進んで生成間隔が速くなっても）フレームレートが極端に悪化しない。
